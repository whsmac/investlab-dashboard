# INVESTLAB 통합 거래 원장 설계안

## 목표

주식 매수·매도, 현금 입출금, 원화/달러 환전을 하나의 거래 원장으로 기록한다. 원장 기록은 보존하고 보유 수량, 이동평균 매입원가, 실현손익, 현금 잔액은 거래를 순서대로 재계산한다. 이 설계는 투자 관리용이며 세금 신고용 계산을 대체하지 않는다.

## 1. 거래 유형

- `BUY`: 주식 매수
- `SELL`: 주식 매도
- `CASH_DEPOSIT`: 외부 자금 입금(통화별)
- `CASH_WITHDRAWAL`: 외부 자금 출금(통화별)
- `FX_CONVERSION`: 한 통화에서 다른 통화로 환전
- `OPENING_POSITION`: 기존 보유 주식의 초기 잔고 등록
- `OPENING_CASH`: 기존 계좌 현금의 초기 잔고 등록

환전은 한 건의 거래에 출금 통화/금액과 입금 통화/금액을 모두 기록한다. USD 입금의 적용환율은 입금 시점의 원화 환산액을 기록하기 위한 값이며, 외부에서 받은 USD 입금과 계좌 내 KRW→USD 환전은 구분한다.

## 2. 데이터 모델

### `ledger_transactions`

| 필드 | 타입/규칙 | 설명 |
|---|---|---|
| `id` | UUID PK | 거래 식별자 |
| `user_id` | UUID, auth.users 참조 | 소유 사용자 |
| `transaction_date` | date | 거래일 |
| `sequence_no` | integer | 같은 날 처리 순서 |
| `transaction_type` | enum/text | 위 거래 유형 |
| `symbol` | text, nullable | 주식 거래 종목 |
| `quantity` | numeric(20,8), nullable | 주식 수량 |
| `unit_price` | numeric(20,8), nullable | 주당 체결 가격 |
| `currency` | text | 주식 체결 통화 또는 현금 거래 통화 |
| `gross_amount` | numeric(20,8), nullable | 거래 총액(계산 가능한 경우 파생) |
| `fees` | numeric(20,8), default 0 | 거래 통화 기준 수수료 |
| `from_currency` | text, nullable | 환전 출금 통화 |
| `from_amount` | numeric(20,8), nullable | 환전 출금액 |
| `to_currency` | text, nullable | 환전 입금 통화 |
| `to_amount` | numeric(20,8), nullable | 환전 입금액 |
| `applied_fx_rate` | numeric(20,10), nullable | KRW per USD 등 명시한 환율 방향 |
| `note` | text, nullable | 메모 |
| `created_at` / `updated_at` | timestamptz | 감사/수정 시각 |

실제 구현 시 DB CHECK 제약조건으로 거래 유형별 필수 필드, 양수 수량/금액, 통화 및 환율 방향을 검증한다. 사용자별 RLS를 적용한다. 거래 기록은 사용자 계정 안에서만 조회·수정 가능해야 한다.

### 계산 결과

초기 버전은 원장 기록을 기준으로 애플리케이션에서 거래일·sequence_no 순서로 재계산한다. 조회 성능이 필요해지면 뷰나 캐시 테이블을 검토한다. 계산 결과를 거래 기록의 원본 값처럼 직접 수정하지 않는다.

## 3. 이동평균법

매수:
- 매수 원가 = 수량 × 체결 단가 + 매수 수수료
- 새 잔여 원가 = 기존 잔여 원가 + 매수 원가
- 새 보유 수량 = 기존 수량 + 매수 수량
- 새 평균 원가 = 새 잔여 원가 ÷ 새 보유 수량

매도:
- 매도 직전 평균 원가로 매도 수량의 원가를 계산한다.
- 실현손익 = 매도 대금 − 매도 수량 × 매도 직전 평균 원가 − 매도 수수료
- 잔여 원가 = 매도 전 잔여 원가 − 매도 수량 × 매도 직전 평균 원가
- 매도 수량은 보유 수량을 초과할 수 없다.
- 전량 매도 후 수량과 잔여 원가는 0으로 만든다. 이후 재매수는 새 평균 원가를 형성한다.

거래 수정·삭제·과거 거래 추가 시 해당 종목의 이후 거래를 모두 다시 계산한다. 같은 날짜 거래는 sequence_no로 순서를 결정한다.

## 4. 현금 및 환율

현금 잔액은 통화별로 계산한다.

- 현금 입금: 해당 통화 잔액 증가
- 현금 출금: 해당 통화 잔액 감소, 잔액 부족 시 경고/차단
- 주식 매수: 거래 통화 현금 감소
- 주식 매도: 거래 통화 현금 증가
- 환전: from_currency 잔액 감소, to_currency 잔액 증가

USD 외부 입금은 USD 잔액을 증가시키고, 적용환율(원/USD) 및 원화 환산액을 기록한다. USD 현금의 원화 평가액은 현재 환율로 계산하며, 입금 당시 환율과 현재 환율 차이는 주식 실현손익과 분리해 환율 효과로 보고한다.

환전 기록에는 실제 출금액과 실제 입금액을 저장한다. 적용환율은 `to_amount / from_amount`와 일치하는지 검증하되, 은행이 제시한 기준 환율과 수수료를 별도 입력할 수 있도록 한다. 수수료 통화가 거래 통화와 다르면 수수료 통화/금액 필드를 추가한다.

## 5. 초기 잔고 이전

기존 데이터는 자동 삭제하거나 즉시 대체하지 않는다.

1. 기존 `holdings`의 종목별 수량과 평균 매입가를 확인한다.
2. 종목별로 `OPENING_POSITION`을 생성한다. 초기 수량과 단가는 기존 값과 같아야 한다.
3. 현재 USD 현금은 `OPENING_CASH`로 등록한다. 가능한 경우 실제 취득 환율/원가를 입력하고, 모르면 원가 환율 미상으로 표시한다. 알 수 없는 환율을 임의로 만들지 않는다.
4. 기존 현금 잔액과 거래 원장 계산 잔액을 비교한다.
5. 기존 보유 수량·평균 매입가·총원가가 일치함을 검증한 후 대시보드 연결을 전환한다.
6. 마이그레이션은 사용자별로 한 번만 실행되도록 idempotency key 또는 고유 제약조건을 둔다.

기존 평균 매입가가 수수료 포함 여부를 알 수 없다면, 초기 잔고 원가를 기존 대시보드 값과 동일하게 유지하고 해당 원가의 포함 기준을 메모한다.

## 6. 구현 단계

1. 스키마 및 RLS 마이그레이션 작성/검토
2. 초기 잔고 이전 및 취소 가능한 검증 절차
3. 매수·매도·현금 입출금·환전 입력 화면
4. 원장 계산기와 이동평균법 단위 테스트
5. 기존 대시보드와 계산 결과 대조
6. 거래 원장 기반 통합 주가 그래프 개발

## 7. 필수 검증 시나리오

- 10주를 100에 매수하고 10주를 120에 매수 → 평균 원가 110
- 8주를 130에 매도(수수료 0) → 실현손익 160, 잔여 12주, 잔여 원가 1320
- 전량 매도 후 재매수 → 이전 원가 잔존 없이 새 원가 계산
- 보유량보다 많은 매도 시도 → 거부
- KRW→USD 환전 → 두 통화 잔액의 변동이 환전 내역과 일치
- USD 외부 입금 → USD 잔액과 입금 당시 원화 환산액이 함께 기록
- 거래 내역 수정/삭제 → 이후 잔고·평균 원가·실현손익 재계산
- 동일 날짜 여러 거래 → sequence_no 순서대로 일관되게 처리
- 사용자 간 데이터 접근 차단(RLS)
- 초기 잔고 이전 전후 기존 포트폴리오 수량과 원가 일치

## 8. 범위 밖/후속 작업

- 세금 신고용 원가 및 세금 계산
- 복수 계좌별 원장/통화 지갑 확장
- 자동 브로커 거래내역 가져오기
- 환전 손익의 세부 실현/미실현 분리 계산
- 통합 주가 그래프의 거래 시점 표시

이 문서는 설계 기준이다. 실제 Supabase 스키마 변경은 별도 마이그레이션과 테스트를 거친 후 적용한다.
