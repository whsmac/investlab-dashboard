# INVESTLAB 가상 매매 시뮬레이터 — 1단계 사용자 검증

## 테스트 전 확인
- PR #34의 **Draft 브랜치**에서 제공하는 `virtual-trade-simulator.html`을 실행한다. 운영 대시보드에 반영되거나 PR이 병합된 상태가 아니다.
- 기존 포트폴리오(`index.html`)와 시뮬레이터는 **같은 브라우저, 같은 프로토콜·호스트·포트(동일 origin)** 에서 열어야 `localStorage` 보유·관심·거래이력 종목을 공유한다.
- 종목관리가 화면에 표시되더라도 초기 예시(SEED)만 표시되는 경우 `investlab_holdings` 저장값이 없을 수 있다. 이 경우 시뮬레이터는 보유종목을 자동으로 불러오지 못한다. **예시값을 실제 보유량으로 취급하지 않는다.**
- 시뮬레이터는 기존 보유정보를 읽기만 하며, 실제 보유수량·매매원장·Supabase를 변경하지 않는다.

## 사용자 테스트 순서
1. 기존 포트폴리오에서 실제 보유종목·수량·평균 취득단가가 저장되어 있는지 확인한다.
2. 같은 origin의 `virtual-trade-simulator.html`을 열고 '현재 포트폴리오 보유정보 다시 불러오기'를 누른다.
3. 보유종목의 **수량 및 평균 취득단가**가 원본과 일치하는지 확인한다. 관심/거래이력 종목은 종목 선택 후보로만 표시된다.
4. 시작 현금(USD)을 확인한다. `USD-CASH`가 저장되어 있으면 자동 반영되고, 없으면 직접 입력한다. 과거 `USD` 심볼은 자동으로 현금 처리하지 않는다.
5. 각 보유종목의 **최종 가정 주가**를 입력한다. 비어 있는 가격은 현재가 또는 평균 취득단가로 추정하지 않는다.
6. 가상 거래에서 TSLA 매도 후 SOXL 매수처럼 **순서대로** 거래를 추가한다. 각 거래의 종목·수량·USD 거래가격·수수료를 입력한다. 새 종목 SOXL의 최종 가정 주가도 입력한다.
7. '시나리오 계산'을 누르고 가상 거래 단계별 현금, 최종 수량, 최종 평가액, 보유 유지 대비 차이를 확인한다.
8. 기존 포트폴리오 화면을 새로고침해 실제 보유종목과 수량이 **변경되지 않았는지** 확인한다.
9. 양도세는 별도 원화 손익·세율·공제액 등 가정이 있어야 계산한다. 미입력 상태의 USD 매매손익을 실제 신고세액으로 취급하지 않는다.

## 검증 기준
- TSLA 10주(평균단가 $100), 현금 $100에서 TSLA 2주를 $200에 매도하면 가상 잔여 TSLA는 8주, 가상 현금은 $500(수수료 0)이다.
- TSLA 최종 가정 주가 $150라면 가상 최종 평가액은 $1,700이고, 매매하지 않고 보유했다면 $1,600이므로 차이는 +$100이다.
- 원본 TSLA 보유수량은 계속 10주여야 한다.

## 오류 보고
- 사용한 화면 URL(origin 포함), 불러온 종목 개수, 현금 자동반영 여부, 오류 메시지, 계산 전후 수량·현금·평가액을 함께 기록한다.
- 실제 계좌번호, 로그인 토큰, Supabase 키 등 민감정보는 공유하지 않는다.

## 미완료 범위
- 다른 기기/도메인 사이의 자동 동기화는 1단계 로컬 저장소 연동의 범위가 아니다.
- PR #34는 Draft이며 운영 화면·운영 Supabase에 배포하지 않는다.
- 시뮬레이터 전용 CI 통과와 전체 대시보드 CI 통과는 별도이다.
