# 초기 잔고 이전 및 대조 계획 (읽기 전용)

## 목적과 안전 경계

통합 원장을 기존 대시보드에 연결하기 전에 현재 보유 내역을 기준값으로 보존하고, 원장으로 이전한 결과가 정확히 일치하는지 확인한다.

- 이 계획은 읽기 전용 검토용이다. 기존 데이터를 변경하거나 삭제하지 않는다.
- `public.holdings`와 브라우저의 `localStorage` 값이 다를 수 있으므로 둘을 같은 것으로 가정하지 않는다.
- Supabase 로그인 사용자의 데이터만 조회한다. RLS를 우회하거나 service-role 키를 브라우저에 넣지 않는다.
- 이전 데이터와 원장 계산값이 일치하기 전에는 대시보드의 기존 계산을 원장으로 교체하지 않는다.

## 1. 기준 스냅샷 확보

이전 작업을 시작하기 직전에 다음 값을 내보내거나 화면/CSV로 보관한다.

1. 현재 로그인한 사용자의 `public.holdings`: symbol, shares, avg_cost.
2. 브라우저의 `investlab_holdings` 로컬 저장값: symbol, shares, avg_cost. 저장값은 해당 브라우저에서만 확인한다.
3. USD-CASH 보유량/현금 잔액.
4. 대시보드에 표시되는 종목별 총원가(수량 × 평균 매입가), 총 평가액 및 총자산.
5. 스냅샷 생성 시각, 통화, 로그인 계정 식별자(비밀정보는 제외).

두 원본이 다르면 자동으로 어느 한쪽을 덮어쓰지 않는다. 사용자가 기준으로 삼을 원본을 결정한 후에만 다음 단계로 진행한다.

## 2. 이전 매핑

| 기존 값 | 원장 기록 |
|---|---|
| 종목의 양수 보유 수량 및 평균 매입가 | `OPENING_POSITION`, symbol, quantity, unit_price=기존 평균 매입가, currency=해당 종목 통화 |
| USD-CASH 잔액 | `OPENING_CASH`, currency=USD, gross_amount=현금 잔액 |
| 수량 0인 종목 | 원장에 초기 포지션을 만들지 않고 종목 목록으로만 유지 |
| 평균 매입가를 알 수 없는 포지션 | 추정하지 말고 보류 목록에 기록 |

초기 잔고 기록은 사용자별·이전 실행별 고유 `idempotency_key`를 사용한다. 같은 이전을 두 번 실행해도 중복 생성되지 않는지 먼저 확인한다.

## 3. 대조 규칙

종목별로 다음 조건을 모두 확인한다.

- 기존 수량과 원장 재계산 수량 차이 = 0 (수량 정밀도 범위 내).
- 기존 평균 매입가와 원장 재계산 평균 원가 차이는 표시 반올림 오차 이내.
- 기존 총원가와 원장 잔여 원가 차이는 허용 오차 이내.
- USD 현금 잔액은 기존 값과 정확히 일치.
- 총 평가액 및 총자산 차이는 같은 시세·환율 스냅샷을 사용했을 때만 비교한다.
- 원장에 중복된 초기 잔고가 없고, 기존 거래 내역과 초기 잔고가 중복 반영되지 않는다.

## 4. 중단 조건

다음 중 하나라도 해당하면 대시보드 전환을 중단하고 차이를 조사한다.

- 기존 클라우드 보유 내역과 로컬 저장값이 다르며 기준 원본이 확정되지 않음.
- 평균 매입가/현금 잔액이 누락되었거나 원화 환산 원가를 추정해야 함.
- RLS가 다른 사용자 데이터를 차단하는지 검증되지 않음.
- 초기 잔고 재실행 시 중복 방지가 확인되지 않음.
- 수량·원가·현금 잔액의 대조가 통과하지 않음.

## 5. 진행 순서

1. 사용자가 현재 스냅샷을 보관한다.
2. 별도 테스트 계정/테스트 프로젝트에서 마이그레이션과 RLS를 시험한다.
3. 테스트 데이터로 초기 잔고를 등록하고 대조표를 생성한다.
4. 매수·매도·환전 테스트 이후에도 대조표가 맞는지 확인한다.
5. 사용자가 결과를 검토하고 승인한 뒤에만 운영 프로젝트 적용을 계획한다.

**현재 상태:** 문서화된 계획 단계. Supabase에 새 테이블을 만들거나 데이터를 이전하지 않았다。
