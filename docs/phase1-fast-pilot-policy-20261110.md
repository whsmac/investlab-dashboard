# INVESTLAB 1차 개발 실행 원칙 (2026-11-10)

## 사용자 확정 방침
1. 기존 계획의 핵심 기능을 우선 빠르게 완성하여 실제 사용 가능한 1차 버전을 만든다.
2. 유료 데이터 구매, 장시간 소요되는 데이터 확보·정제, 고난도 자동화 등은 1차 완료를 막지 않도록 후속 개발로 이관한다.
3. 구현된 기능은 먼저 Pilot Test로 사용한다. 사용 중 발견한 오류·불편·개선안을 기능/모듈별로 기록하고, 검증 결과에 따라 다음 개발 계획을 수립한다.

## 1차 완료 우선순위
- 가상 매매 시뮬레이터: 일반 입력 UI, 다단계 매매·전략 비교, 현금/수량/평균원가/실현손익, **입력값 기반의 세금 추정**과 명확한 한계 표시
- 공유 기업 데이터: 이미 TEST에 저장된 CSV 주가 관측값과 6개 기업의 기존 조회 흐름 활용. 수익·CAPEX는 확보된 자료 범위 내에서 조회하며 결측을 숨기지 않는다.
- 기존 대시보드와 개발 화면의 안전한 탐색 동선
- 핵심 계산 및 입력 검증 테스트, Pilot Test용 점검표

## 1차에서 후순위로 이동
- 유료 주가/재무 데이터 확보, 모든 주가의 외부 원본 대조, 자동 정제
- 복잡한 SEC/외부 데이터 자동 수집 파이프라인 완성
- 고도화된 AI 투자 효율 분석 및 예측
- 실제 계좌 연동, 세무 신고 수준의 세액 확정

## 운영·안전 경계
- 기존 개인 대시보드, 운영 Supabase, 실제 투자원장은 변경하지 않는다.
- TEST DB 추가 쓰기·스키마 변경 및 PR 병합은 명시적 승인 없이는 하지 않는다.
- 기존 Gemini 생성 CSV 4,938행은 Pilot Test용으로 유지하며 검증된 실거래 데이터로 표시하지 않는다.
- 가상 거래는 실제 원장에 저장하지 않는다. 세금 추정은 사용자 입력 가정과 누락 데이터가 명확히 드러나야 한다.
- 회사 환경의 Supabase 연결 제약 때문에 회사에서 SQL 실행을 요구하지 않는다.

## Pilot Test 피드백 기록 형식
모듈 / 재현 절차 / 기대 결과 / 실제 결과 / 심각도(차단·불편·개선) / 처리 시점(1차 수정·후속 개발).

## 1차 완료 판단
핵심 화면이 실행되고 주요 시나리오가 재현 가능하며, 데이터 출처·세금 추정 한계가 명시되고, 실제 원장·운영 DB에 영향이 없을 것. 후속 개선사항은 별도 목록으로 관리한다.
