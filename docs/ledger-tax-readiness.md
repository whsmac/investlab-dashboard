# 양도소득세 기능 준비사항

## 목적과 범위

미국주식 양도소득세 계산은 통합 원장 검증이 끝난 다음 별도 모듈로 구현한다. 이 문서는 현재 원장 설계에서 향후 세금 계산에 필요한 데이터가 보존되는지 점검한 결과이며, 세금 계산 기능 자체를 구현하거나 운영 데이터에 적용하지 않는다.

## 현재 설계에서 확보되는 정보

- 거래일: `transaction_date`
- 종목, 수량, 거래단가: `symbol`, `quantity`, `unit_price`
- 거래 통화: `currency`
- 거래 수수료: `fees`
- 거래 순서: `sequence_no`
- 거래 정정·삭제 후 재계산: 원장 전체 replay 방식

## 확인된 공백

미국주식 매수·매도 거래별로 **세법상 원화 환산에 사용할 환율 또는 확정 원화 취득가액·양도가액을 명시적으로 보존하는 필드가 없다.**

현재 `applied_fx_rate`는 환전 거래의 환율 정보에 사용되며, 주식 매수·매도 시점의 세법상 환율을 기록한다는 규칙은 정의되어 있지 않다. 환전 거래의 실제 환율을 매수·매도 거래의 세금 환율로 간주해서는 안 된다.

따라서 양도소득세 모듈을 구현하기 전에 다음 중 하나를 명시적으로 설계해야 한다.

1. 각 매수·매도 거래에 세금 계산용 적용 환율을 보존한다.
2. 또는 세법상 환율 기준과 출처·적용일을 보존하고, 이미 확정한 원화 취득가액·양도가액을 재현할 수 있게 한다.

단순히 현재 환율로 과거 거래를 환산하거나, USD 실현손익에 현재 환율을 곱하는 방식은 사용하지 않는다.

## 향후 세금 모듈 요구사항

- 과세연도별 양도 거래를 집계하고 연도별 손익을 통산한다.
- 연간 기본공제는 해당 연도에 한 번만 적용한다.
- 취득가액과 양도가액은 세법상 환산 기준 및 인정되는 필요경비를 반영해 원화로 계산한다.
- 세율·공제액은 코드 곳곳에 고정하지 않고 적용연도별 설정 또는 명시적 정책으로 관리한다.
- 해외주식 외 다른 과세대상 자산의 손익이 포함되지 않은 경우 결과를 '해외주식 거래만 반영한 추정치'로 표시한다.
- 거래 추가·수정·삭제 시 해당 연도의 세금 계산을 원장 데이터에서 다시 산출한다.
- 증권사 세금자료와 대조하는 테스트 사례를 마련하며, 최종 신고액을 보장하는 세무신고 대체 기능으로 표시하지 않는다.

## 진행 순서와 안전 경계

1. 현 단계에서 원장 계산 및 기존 잔고 대조를 우선한다.
2. 세금 기능 구현 전 환율 및 원화 금액 보존 정책을 결정한다.
3. 세금 계산기는 원장 계산기와 분리하고 독립 테스트를 작성한다.
4. 실제 데이터 대조와 검토가 끝나기 전에는 운영 대시보드에 연결하지 않는다.

**현재 상태:** 설계 검토 문서만 추가. 세금 계산 기능, 데이터베이스 변경, Supabase 배포 및 운영 대시보드 전환은 수행하지 않았다.
